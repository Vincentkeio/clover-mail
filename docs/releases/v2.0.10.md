修复旧版本首次更新时未执行新版空间清理的问题。

- 旧版本同步源码后，通过原有更新入口记录镜像归属并执行新版清理，无需先更新一次再重复操作。
- 拉取前同时记录项目容器和 Compose 当前指向的镜像；更新健康检查通过后，回收无容器引用且归属可确认的旧镜像，以及带 Clover 标识的历史预览镜像。
- 旧版备份保留策略在本次更新内迁移为只保留最近一组完整备份；完整备份失败时保留旧镜像和回滚快照。
- 历史共享构建器仅按明确的 Clover 缓存记录定向清理；共享层、其他项目标签、正在使用的镜像和全部数据卷继续保留。
- 后续更新在同步源码后切换到新版更新脚本，避免继续运行已经替换的旧代码。

归属不明的历史第三方镜像或通用构建缓存不会仅因“未使用”而被删除。2.0.8 已撤回，其旧更新脚本含全局清理命令；曾安装此撤回版本的实例应先替换服务器上的更新脚本，再启动更新。

仅 2.0.8：在 Clover 项目目录执行以下命令，下载成功后才替换旧脚本并更新：

```bash
curl -fsSL https://raw.githubusercontent.com/Vincentkeio/clover-mail/v2.0.10/scripts/upgrade.sh -o scripts/upgrade.sh.new && mv scripts/upgrade.sh.new scripts/upgrade.sh && bash scripts/upgrade.sh
```
